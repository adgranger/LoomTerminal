# P2-02 — `tools/xterm-oracle`: expected snapshots from xterm.js itself

- **Status:** done
- **Depends on:** P2-01
- **Size:** M

## Goal

A Node.js script that runs `@xterm/headless` 6.0.0 (the version LoomTerminal ports) on every fixture input and
writes the expected snapshot JSON, in exactly the format of P2-01.

## Files to create or change

- `tools/xterm-oracle/package.json` — create (`"type": "module"`, dependency `"@xterm/headless": "6.0.0"` pinned
  exactly, plus `"@xterm/addon-unicode11"` at the version matching 6.0.0 — check npm and pin exactly)
- `tools/xterm-oracle/package-lock.json` — generated by `rtk npm install` and committed
- `tools/xterm-oracle/oracle.mjs` — create
- `tools/xterm-oracle/README.md` — create (what it is, how to run, "never edit the generated JSON by hand")
- `.gitignore` — add `tools/xterm-oracle/node_modules/`

## Design decisions (already made — do not change)

- Usage: `node oracle.mjs <fixtures folder> [--check]`. It walks `scenarios/*.input` and `recorded/*.vtrec`, and
  writes `<name>.json` next to each. `--check` writes nothing and exits 1 if any JSON would change (for CI later).
- The terminal is created with the same options as `TerminalCore` defaults (scrollback 1000, Unicode 11 active
  through the addon, `allowProposedApi: true` for the unicode API), size from the fixture.
- The `.input` decoder and JSON writer follow the phase 2 conventions to the letter; keys are written in the
  documented order (build objects in that order; `JSON.stringify(value, null, 2)` + `\n`).
- Writes go through `terminal.write(data, callback)`; the snapshot is taken after the last callback.
- Node.js ≥ 20 is required (document it); CI does not run the oracle: the JSON files are committed.
