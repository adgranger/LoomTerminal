# Phase 2 conventions — conformance and performance

Phase 2 proves that `LoomTerminal.Core` behaves like xterm.js on real input, and measures it. Read
[ADR 0003](../../adr/0003-testing-strategy.md) first.

## The screen snapshot format (shared by C# and the Node oracle)

One JSON document per fixture, written with 2-space indentation, `\n` line endings, keys in this order:

```json
{
  "cols": 80,
  "rows": 24,
  "cursor": { "x": 0, "y": 0, "visible": true },
  "activeBuffer": "normal",
  "modes": { "applicationCursorKeys": false, "bracketedPaste": false, "insert": false, "origin": false, "wraparound": true, "mouseTracking": "none" },
  "title": "",
  "lines": [
    { "text": "hello", "wrapped": false, "runs": [ { "start": 0, "length": 5, "fg": "default", "bg": "default", "flags": [] } ] }
  ]
}
```

- `lines` holds the **viewport** rows (`ybase … ybase + rows - 1`), each `translateToString(true)`.
- `runs` group consecutive cells with the same attributes; only cells up to the trimmed length are included.
- Colors: `"default"`, `"p16:<n>"`, `"p256:<n>"`, `"rgb:<rrggbb>"`. Flags, in this order: `bold`, `dim`, `italic`,
  `underline:<style>`, `blink`, `inverse`, `invisible`, `strikethrough`, `overline`.
- Wide characters: the cell after a wide character has width 0 and is part of the same run.

## Fixture layout

```
tests/LoomTerminal.Core.Tests/Conformance/Fixtures/
  scenarios/<name>.input       escape-coded input (see below), hand-written (P2-03)
  scenarios/<name>.json        expected snapshot, generated by the oracle
  recorded/<name>.vtrec        raw session recorded through ConPTY (P2-04)
  recorded/<name>.json         expected snapshot, generated by the oracle
```

`.input` files are UTF-8 text where `\e`, `\a`, `\r`, `\n`, `\t`, `\xHH` and `\uHHHH` are escapes (decoded by both
sides with the same rules), and a line starting with `#!resize <cols> <rows>` resizes the terminal at that point.
Initial size is 80×24 unless the first line is `#!size <cols> <rows>`.

`.vtrec` files are text, one event per line: `O <base64 bytes>` (output from the pty), `R <cols> <rows>` (resize).

## How to record

Recordings need a real ConPTY, so they are made on Windows, from the repository root, with neutral folders (no user
names, `C:\Users\…` paths, tokens or e-mail addresses in the output: decode the base64 and review each file):

```powershell
dotnet run --project samples/LoomTerminal.PtyConsole -c Release -- --record tests/LoomTerminal.Core.Tests/Conformance/Fixtures/recorded/cmd-dir.vtrec --size 100x30 cmd.exe /c dir C:\Windows\System32\drivers\etc
```

`--record <file>` and `--size <cols>x<rows>` come before the command line; with `--size` the size is fixed (no window
watching), so the recording is reproducible. The file starts with an `R <cols> <rows>` line. Then run the oracle on the
new files (see Commands).

Run the commands from PowerShell with stdin redirected (`$null | & <exe> ...`), not from Git Bash (it rewrites `/c`).
Use `git --no-pager` (the pager waits for a key) and avoid double quotes inside `pwsh -Command` text (the command-line
join drops them).

Interactive sessions (vim, htop, less under WSL, PSReadLine editing) are **manual**: ask the user to record them.
